# Behaviour specification

Every row names a behaviour, what the tool must do, and the test(s) proving it.
The suite enforces this file mechanically (`tests/test_spec_coverage.py`): a row
citing a test that does not exist fails, and a test no row claims fails too, so
the citations cannot drift from the suite. The prose is only as good as its
review. A defect gets registered here as a strict-xfail row until its fix
promotes the test. The register is empty.

Citations are written as the test module name, two colons, then the function name.
